§0 СВОДКА · One vault, one voice

This is the fourth surface of the g2 design system, after the GUI, the terminal and the wrist. Same seeds, same token names, same stamps, same label grammar. What changes is the host: Obsidian is the one surface that already has a token contract of its own, a few hundred CSS variables under .theme-dark and .theme-light. The theme maps the bureau's tokens onto that contract once, and the rest is a component layer the size of a long memo. Every example on this page is a real Obsidian class name with the real theme loaded on top, so the paper toggle above re-renders every window.

ТРИ ПРАВИЛА · the three rules

1. The contract first, selectors second. Whatever Obsidian exposes as a variable is set through the variable. A selector is written only where the contract has no slot (uppercase on a ledger key, the frame on a callout, the eyebrow on a stamp).

2. Plugin DOM never enters the theme. Kanban, Bases and Dataview get a snippet each, defensive, installed separately. A plugin that changes its markup breaks one snippet, not the vault.

3. The body is not mono. Reading is what a vault is for. Body text follows the system: PT Sans on the bureau, PT Serif on paper. Mono is the explorer, the tabs, the keys, the code and the status bar.

ПРИМЕЧАНИЕ · note

The theme that ran in three vaults since June (the same Nirvytekh name, a hand-mixed palette, serif body, dark only) is superseded by this one. Hexes that differed from the generated tokens were the hand palette drifting, not decisions; the contrast gate now covers every pair the vault reads. The vault keeps its name, its folder icons and its plugins; only the sheet changes.

§1 КОНТРАКТ · The contract map

No new colour exists for Obsidian. tokens.obsidian.css puts the g2 tokens on .theme-dark (bureau) and .theme-light (paper), then assigns Obsidian's variables from them. Three things the app wants that the other emitters never needed are computed in Python: the accent as an HSL triple (--accent-h/s/l, which Obsidian uses to derive its own accent ramp), every token as an RGB triple (callouts and the canvas read rgb(var(--callout-color))), and the eight-colour extended palette folded onto the bureau's few hues.

ПРИМЕЧАНИЕ · note

Shape and depth are set through the contract too: every --radius-*, --*-radius and --shadow-* slot is zero or none. Fonts go through --font-text-theme (the body, which follows the system), --font-interface-theme (sans, so settings prose stays readable) and --font-monospace-theme. The chrome gets mono per selector in the component layer, not through the interface slot.

§2 ЛИСТ · The sheet is the GUI's rendered prose

A note in reading view is the GUI page's "rendered prose" component with a frontmatter header on top. Headings are mono, the first two uppercase with a rule beneath, as in every document of the suite. Paragraphs are the body face. Links are gold and underlined in the frame colour; an unresolved link is muted and dashed, a form not yet filed. A blockquote is a note in the second hue, because a quotation is an annotation, not a decision.

Standard 004 · the fourth surface

The Directorate notes that a vault is read in long sessions, and that a long session in monospace is a cost the reader pays and the bureau does not refund. The body is therefore the system's body face, with emphasis in the same ink, inline code in a faint frame, and a highlight in amber at a quarter strength. Internal references are filed documents; a reference to a document not yet written is pending; an external source is dotted.

Procedure

Every component below is drawn only with the tokens of §1. The list marker is muted, the checkbox is a square, and a completed item is struck through in the faint ink rather than removed: the ledger keeps its rows.

  • Obsidian variables first, selectors second
  • Plugin DOM in snippets, never in the theme
  • Body text in the system's face
  • Map the contract
  • Write the component layer
  • Install in three vaults

Annotation

A quotation is an annotation on the record, not a ruling on it. It takes the second hue and a left rule. Red is reserved for decisions, and a blockquote has decided nothing.

§3 ИЗВЕЩЕНИЯ · Callouts are stamped notices

A callout is the GUI's frame panel with a title bar: one 1 px frame in its own colour, a mono uppercase title on a wash of the same colour at ten percent, the panel behind the content. Obsidian's fourteen callout types fold onto six colours. Four of them are the canon's decisions and carry the stamp word as an eyebrow, Cyrillic first, as every stamp in the suite. Writing [!approved], [!rejected], [!order] or [!review] in a note gives the stamp directly; the usual success, failure, todo and warning map onto the same four.

ПРИМЕЧАНИЕ · note

The Admonition plugin renders its blocks as the same .callout markup in current versions, so it inherits all of this without a snippet. Custom admonition types that are not in the list above fall back to Obsidian's default, which the contract paints in the note hue.

§4 ВЕДОМОСТЬ · Properties are the document header

The frontmatter block is the bureau's numbered header, drawn as a framed ledger: mono uppercase keys in the muted ink, values in the body ink, one faint rule per row, list values as outline pills. It sits on the panel so the sheet below reads as the body of the form. Editing a value puts the well behind it and a gold rule under the row; nothing else moves.

§5 МЕТКИ · Tags, links and code marks

The June theme filled every tag in gold. In a note with six tags that is six gold fields in running text, and the field is supposed to be quiet. A tag is now an outline chip, mono, gold text in a frame, filled only on hover. Links keep the GUI's three states. Inline code sits in the well with a faint frame; a code block takes the full frame and a mono copy button in the corner.

§6 АРХИВ · The window is the filing room

Around the sheet, Obsidian is chrome: ribbon, explorer, tabs, status bar, menus, prompts, settings. All of it is mono and most of it is set by the contract alone. The ribbon, the title bar and the status bar sit on the well, the deepest surface; the explorer on the panel; the sheet on the field. Folders are ledger keys (uppercase, muted), files are entries. The active file carries a gold left rule, the active tab a gold top rule: a frame weight, not a fill.

§7 ДОСКА · Kanban is a despatch board

The Kanban plugin draws floating cards in rounded lanes. The g2-kanban snippet makes a despatch board of it: lanes are framed sheets on the panel with a 3 px top rule, cards are slips on the field, titles are ledger keys. The snippet sets structure only. Which lane means what is a vault decision, so each lane exposes --g2-lane and the vault's own snippet colours its columns with the stamp grammar, as below. §8 РЕЕСТР · Bases and Dataview are filterable ledgers

A Base is a ledger the reader can sort. The g2-bases snippet gives it the table grammar (mono uppercase keys, tabular figures, a frame, the selection wash on hover) and reads the cell values: a value that spells a decision in the canon's English takes the stamp colour, a negative number takes the red at body size, a false is faint. Dataview tables inherit the theme's ledger; the g2-dataview snippet covers inline fields and the error box, which is a rejected form.

§9 БЛАНК · Light mode is the paper form

The system's rule is that paper is chosen by the user, never by the clock or the operating system. In Obsidian the user chooses it in Settings › Appearance › Base color scheme, and that choice is .theme-light. The generated file puts the paper tokens there and the body switches to PT Serif, as the GUI does on paper. The June theme was dark only; this one is not, and "adapt to system" is the one Appearance setting the standard asks the reader to leave off. Export to PDF goes through @media print, which is paper on either theme.

§10 ВНЕ КАНОНА · What the theme does not do

The GUI and TUI lists apply. These are the Obsidian-specific ways to turn the standard into a costume, or the vault into a maintenance burden.

✗A hex in theme.css or a snippetA token or nothing. Colours are born in derive_tokens.py and arrive through the contract.
✗Plugin selectors inside the themeOne snippet per plugin, defensive, enabled by the vault that needs it.
✗Monospace body textPT Sans on the bureau, PT Serif on paper. Mono is the chrome and the code.
✗Gold-filled tags in running textOutline chips. The field stays quiet; gold fills on hover and on the primary button only.
✗Red on a blockquoteA quotation is a note, the second hue. Red is a rejection.
✗Uppercase buttonsSentence case. Uppercase is for stamps, keys and frame titles.
✗"Adapt to system" for the colour schemeThe user picks dark or light. Paper is opt-in, by canon.
✗Embedded font filesFont stacks with fallbacks. Install PT Sans, PT Serif and JetBrains Mono for the full set.
✗Styling make.md spaces and stickersThe vault's own gold icon set stays the vault's. The theme does not reach into make.md's DOM.
✗Editing obsidian/theme.css by handEdit obsidian/src/theme.css and run the generator; the bundle is overwritten.
